## mobile-floating-nav 布局设计更正（单排滑动）

上一条记录的 flex-wrap 自动换行/换列方案被用户否决——「为什么要两排?
收起悬浮框按钮固定在首位,其他的按钮支持滑动就可以了。按钮排数固定为1排」。

最终方案（已落地）：
- **去掉 flex-wrap**，排数固定 1 排：竖排单列 / 横排单行
- **栏内滑动**：竖排 `overflow-y:auto` + max-height；横排 `overflow-x:auto` + max-width；
  按钮 `flex-shrink:0` 防压缩；`scrollbar-width:none` + `::-webkit-scrollbar{display:none}`
  隐藏滚动条；`overscroll-behavior:contain` 防滚动穿透
- **折叠按钮固定在首位**（原在末尾），入口位置稳定；展开后仍是首位
- 测试更新索引断言（折叠=btns[0]），扩到 29 例全过

设计教训：移动端悬浮工具条「数量多」的正确答案是滑动而非换行，
换行会把单屏工具条变成多排面板，破坏单手可达性。

## 排查：白板内编辑笔记光标周期性回文首（用户报障）

现象：在 CardBox 投放生成的白板里编辑卡片笔记，一段时间后光标自动回到文首。
用户已排除 FNS（Fast Note Sync）插件。

排查结论（已核源码）：
- CardBox 投放的白板卡片为 **file 节点**（`type:'file'` 引用 .md，见
  `utils/canvas.ts`），编辑卡片 = 编辑 .md 本体
- CardBox 无周期性写文件/重渲染白板逻辑（main.ts 仅 file-open 折叠属性，
  所有写盘均为命令触发），**插件自身基本排除**
- 剩余嫌疑：① .canvas 文件被同步/外部改写 → Obsidian 重载整个白板视图 →
  内嵌编辑器重建 → 光标复位（最符合"一段时间后"特征）；② Canvas 卡片
  失焦/缩放/切页重渲染；③ 历史 Bug（1.1.1 修过打字丢光标）
- 已给用户两个对照实验：普通标签页编辑（区分 .md 重载 vs 白板渲染）、
  原生空白 Canvas 拖入同篇笔记（区分 CardBox 生成白板 vs Canvas 通用）

**定案（17:40）**：用户实验确认 —— 普通编辑器不跳；**原生空白 Canvas 也跳**；
文件层完全安静（停手 2 分钟零写入）。埋点显示白板卡片内嵌编辑器会被销毁重建
（17:34:03 一次，无伴随写文件）。
**结论：与 CardBox 无关，是 Obsidian Canvas 内核行为**——在 file 节点内编辑时
内嵌编辑器重建导致光标归零。方案：先升级 Obsidian 最新版；再测空白笔记排除
内容因素；使用层规避（长文用普通编辑器、双击卡片在标签页打开编辑）。

**排查教训**：Console 埋点脚本若未刷新页面就贴第二版，新旧脚本的监听会同时
存活（VM808/VM822 双来源），输出会翻倍，容易误判成"文件被写两次"——换脚本
前先 Ctrl+R 刷新清场。

**根因定案（17:50，源码坐实）**：CardBox 的 CardIndex 注册 `vault.on('modify')`
（index.ts:64）→ 500ms 后 scheduleRefresh → refresh 里 `maybeBumpUpdated`
（index.ts:184/192）→ `bumpUpdated` 用 processFrontMatter 重写 frontmatter
updated（frontmatter.ts:391）→ **二次写盘** → Obsidian 检测到打开中的文件又被
改写 → 重载编辑器 → 白板卡片内嵌编辑器重建 → 光标回文首。

- 阈值 `UPDATE_BUMP_THRESHOLD_MS=1000` + 冷却 `UPDATE_BUMP_COOLDOWN_MS=1500`
  （index.ts:12-13）→ 连续打字不触发、停顿几秒后触发，正好是"一段时间后"
- **原生空白 Canvas 也跳**的原因：bump 是文件级监听，与白板来源无关
  （上一轮"与 CardBox 无关"的结论有误——实验 B 时 CardBox 还在运行）
- 空文本卡片不跳：text 节点内容在 .canvas，不写 .md，不触发索引
- **bumpUpdated 不受 writeTimestampFields 设置控制**（该设置只管新建卡片）
- 修复方向：maybeBumpUpdated 增加"文件正在编辑中则跳过"判断（查打开的
  markdown leaf + canvas 内嵌编辑器 DOM），或直接去掉自动 bump

**方案 A 已落地（18:30）**：`index.ts` 新增 `isFileBeingEdited(path)`——
① 遍历 `workspace.getLeavesOfType('markdown')` 匹配 file.path；② DOM 探测
`.canvas-node[data-path="..."] .cm-editor`（CSS.escape 转义，document 缺失
时返回 false 兼容 node 测试）。`maybeBumpUpdated` 在写盘前调用它，正在编辑
的文件跳过 bump，保留"外部改动才同步 updated"语义。
顺带修复：`loadtest.mjs` 的 obsidianMock 缺 `getIcon`（v0.6.5 遗留，报
"getIcon is not a function"）——补 `getIcon: (n) => (n === "more-vertical" ? {} : null)`。
测试：build 通过；npm test（link/box/canvas/graph/rename/diagnose）、

mobilefulltest、logtest 全过。**Playwright 测试（domtest/touchtest/masonrytest）

## 日志定位「点击展开没效果」真正根因（v0.6.9）

用户发来 0.6.8 真机日志，证据链完美：

```
[info] [expand] 切换展开状态 {"id":"测试","now":true}
[info] [render] 渲染完成 {"items":7,"expandedIds":1}   ← items 不变！
```

**结论：展开链路（点击→切换→重渲染）一直是好的**。真问题是：
子卡本身就是顶层卡片、平级显示在列表里。展开只是把它从「平级」
挪到「父卡下缩进」，items 数量不变 → 瀑布流里视觉几乎无变化
→ 用户感知「没效果」。

**修复**：buildCardItems 顶层循环跳过子卡（parent 可见时 continue），
子卡只在父卡展开后出现；父卡不在结果时兜底显示。

**经验（重要）**：
- 「真机问题 vs 测试全绿」时，日志面板是唯一可靠的证据来源。
  日志比截图强：截图看不到状态变化，日志能看到 items/expandedIds
- 排查交互「没反应」，先看**状态是否真的切换**（expandedIds），
  再看**渲染结果是否有变化**（items）——用户感知 = 渲染变化，
  状态切换了但渲染无变化 = 视觉 bug，不是交互 bug
- Writeathon 式层级：子卡默认隐藏，只通过父卡数字展开出现。
  这避免「子卡平级重复显示」的困惑

## visited 去重导致子卡移动失效（v0.6.12）

0.6.10 视觉测试通过但真机没生效。用户截图（点击「测试机比长度」
后它下面没子卡）证明 bug。

**根因**（关键教训）：
```
第一遍：所有卡 visit(depth 0) → visited.add 子卡
父卡 visit：isExpanded → visit(child, depth+1)
但 visited 已有子卡 → return → 子卡永远留在 depth 0
```

`visited` 用作「防止重复」，但 0.6.10 的语义需要「子卡可以 visit 两次
（一次默认 depth 0，一次父卡下 depth 1）」。visited 阻挡了第二次。

**修复**：父卡展开时主动管理位置：
1. 从 result 中 splice 移除子卡的 depth 0 项（从后往前遍历避免下标错乱）
2. visited.delete(child) 释放
3. visit(child, depth+1) 加到父卡后面

收起时无需特殊处理（子卡保留 depth 0）。

**关键经验**：「visited 去重」是防止重复渲染的常用模式，但它假设
「每个 item 只渲染一次」。如果一个 item 可能出现在多个位置（默认 +
父卡下），visited 必须配合「主动 unmark + 主动 remove」才能正确切换
位置。**纯 visited.add 不够**。

expandshot.mjs 验证：展开后 9 张总数不变 + 1 张 is-child + 28px 缩进
+ 3px 边框，截图肉眼可见子卡跨整行移动到父卡下方。
