### 关键实现认知
1. **卡片盒语义**：盒不存卡片，只存条件；卡片自动落入所有匹配的盒，
   所以一张卡可同时属于多个盒。条件间是「与」，但留空的条件不生效。
2. **关键字必须匹配正文全文**：原 Card 只有 200 字 snippet，
   导致关键字漏匹配。新增 searchText 字段（标题+标签+正文，上限 4000 字，小写）。
3. **平铺布局踩坑（重要）**：CSS multi-column 在固定高度的滚动容器内会
   **横向分页**，卡片向右溢出而非向下滚动。手机端实测出现 3 列而非 1 列。
   改用 `display:grid` + `repeat(auto-fill, minmax(var(--col-min), 1fr))` 后正确。
   grid 下还需给 sentinel 和 day-group 加 `grid-column: 1/-1`。
4. **拖拽排序**用 Pointer Events + setPointerCapture，鼠标与触屏同时可用；
   拖拽手柄需 `touch-action: none`，否则移动端会被滚动手势抢走。
5. **双向关系**：linkChild/unlinkChild 必须同时维护父的 children 与子的 parent，
   否则列表视图与扩展视图显示不一致。children 数组顺序即展示顺序。

## 追加 6：★根因确认★ PluginSettingTab 必须收真实 Plugin 实例

加了 onload 兜底后，用户看到 Notice「CardBox 初始化失败」→证明 `setup()` 确实抛异常。
同时卡片列表为空，因为崩在设置页那一步，后面的 `index.build()` 根本没执行到。

### 根因
`src/settings.ts` 里原写法：
```ts
constructor(app: App, private access: SettingAccess) {
  super(app, access as unknown as Plugin);// ❌ 传伪造对象
}
```
`obsidian.d.ts` 中 `PluginSettingTab.getSettingDefinitions()` 标记 **`@since 1.13.0`**，
1.13 起该基类会访问 `this.plugin` 的真实属性（manifest 等）。
用户是 **Obsidian 1.13.4**，正好命中新行为 → 构造期抛异常 → 插件启用失败。
（这也解释了为何早期版本可能没事、而我在旧认知下写出这种代码。）

**修复**：构造签名改为 `(app, plugin: Plugin, access: SettingAccess)`，
`super(app, plugin)` 传真实实例，main.ts 调用改`new CardBoxSettingTab(this.app, this, {...})`。

### 为什么我的 mock 没抓到
`scripts/diagnose.mjs` 里 `PluginSettingTab` 是空实现，来者不拒。
**已加严格校验**：构造时检查 `plugin.manifest.id` 与 `plugin.addCommand`，
并回归验证过「旧写法会被拦住、真实实例通过」。

### 通用教训（写进技能）
1. **绝不把伪造对象 as unknown as 成Obsidian 官方类传给其基类构造函数**；
   官方基类可能读取任意内部属性，且行为随版本变化。要解循环依赖就把
   plugin 与 access 分成两个参数传。
2. 查`obsidian.d.ts` 里的 **`@since`** 标记，能预判新版本行为变化。
3. mock 必须**严格**（校验关键属性），宽松 mock 会给出虚假的绿色通过。
4. onload 整体 try/catch + Notice 是有效诊断手段：把「静默回滚开关」

## 追加 7：★第二个根因★ addClass 不接受含空格字符串

修完 PluginSettingTab 后插件能启用了，但**列表依然空白**。
用户截图关键信息：顶部「全部卡片 367」、标签有计数 → **索引成功，问题在渲染层**。

### 根因
`src/view/CardTile.ts:41`
```ts
if (card.color) el.addClass(`has-color cardbox-color-${card.color}`);  // ❌
```
`addClass` 底层是 `classList.add()`，**不接受含空格的字符串**，抛
`Failed to execute 'add' on 'DOMTokenList': ... contains HTML space characters`。
每张带颜色的卡片都会触发（测试数据 1/4 有颜色）→ 渲染中断 →
`.cardbox-list` 里只剩 sentinel，tileCount=0。
修复：`el.addClass('has-color', \`cardbox-color-${card.color}\`)` 分开传参。

**易混淆点**：`createDiv({ cls: 'a b' })` 的 `cls` **允许**空格，
但 `addClass('a b')` 不允许。两套规则。

### 为什么前面所有测试都没抓到
`loadtest.mjs` / `diagnose.mjs` 的假 DOM 用 `Set` 存类名，来者不拒 →虚假绿灯。
**渲染问题必须用真实 DOM 测。**

### 新增 scripts/domtest.mjs（`npm run test:dom`）
playwright 真实 DOM + 注入 Obsidian DOM 原型扩展 + 425 张假卡片，
加载 main.js → onload → 打开视图 → 统计真实元素数 + 截图。
- 坑1：原型扩展必须在 `setContent` **之后**用 `page.evaluate` 注入，
  `addInitScript` 只对新导航生效，会丢。
- 坑2：`DocumentFragment.prototype` 也要补 createDiv/createEl（IncrementalList 用）。
- 坑3：必须监听 `page.on('pageerror')` 与 `console.error`，否则异常被静默吞掉
  —— 正是靠这个才抓到本bug。

平铺模式 4 列，无异常；截图人工确认颜色条与置顶样式正常。

## 追加 8：卡片扩展 × Obsidian 双链整合（v0.3.0）

基础功能验收通过后，用户要求把卡片扩展与 Obsidian 双链整合。

### 用户决策
- 关联存**frontmatter wikilink**（非正文链接区、非两边都写）
- 正文里的 `[[]]` **自动当作扩展卡片**（不是「待确认」模式）

### 实现
1. **新增 `src/utils/link.ts`**：wikilink 解析/生成。
   `parseLinkTarget` 支持 `[[id]]`、`[[id|别名]]`、`[[id#锚点]]`、`[[folder/id]]`、
   `[[id.md]]`、以及**旧的纯 id**（向后兼容，已有卡片无需迁移）。
   写入统一用 `toLinkList()` → `[["[[id]]"]]`。
2. **CardService 全部写操作改写 wikilink**：addChild / linkChild / unlinkChild /
   reorderChildren / createCard(parent)。
   新增 `appendBodyLink(card, targetId)`：在正文末尾追加 `[[id]]`，
   已存在则返回 false 不重复写（用正则检测，注意 id 含连字符需 escapeRegExp）。
3. **Card 新增 `bodyLinks` 字段**，由索引层 `fillBodyLinks()` 从
   `metadataCache.getFileCache().links` + `getFirstLinkpathDest()` 填充。
   **用 metadataCache 而非自己正则解析正文**，可正确处理别名、代码块内链接等。
   build() 与 refresh() 两条路径都要调用。
4. **CardIndex 新增三个方法**：
   - `extensionsOf(card)` → `{card, source: 'explicit'|'body'}[]`，
     frontmatter children 在前（可排序），正文双链按出现顺序追加，去重。
   - `extensionCount(card)`：列表角标口径与扩展视图一致。
   - `backlinksOf(card)`：反查谁引用了当前卡，**排除已是其扩展卡片的**避免重复。
5. **扩展视图**：来源标识badge（「已关联」/「正文双链」，后者虚线左边框）、
   反向链接区（可一键「设为当前主卡的扩展卡片」）、
