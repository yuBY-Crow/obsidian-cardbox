## 手机端新建卡片重设计为简单扁平（v0.6.24）

用户要求：简单扁平、少边框、正文区大、支持编辑标题、保留保存 + 连续创建。

**设计原则**：零边框零分割线，靠字号（标题 20px/600 vs 正文 16px）
与字重区分层级，正文 flex:1 撑满（实测占容器 87%）。

**结构简化**：
- 删掉 .cardbox-capture-title-row 包裹层，标题 input 直接是 contentEl 首个子元素
- 标题 placeholder 改语义化「标题」（原来是「写作就像马拉松」）
- 标题 Enter 跳正文；默认聚焦正文（正文是主角）
- 删掉 autosize 机制（flex 撑满代替动态算高度）

**样式**：容器改 --background-primary（一张纯净的纸）；
标题/正文/footer/mode 全部 border: none + background: transparent；
保存按钮是界面里唯一的实心元素；移动端 min-height 44px。

**文案**：连续模式 → 连续创建。

**又一次踩同样的坑**：styles.css 尾部「旧样式兼容块」会覆盖新样式。
上次是 .cardbox-capture-input（v0.6.22），这次是 .cardbox-capture-footer。
教训：改 CaptureModal 样式时先 grep 整个 styles.css 看有没有同名选择器
在后面重复声明，CSS 后者优先。

**测试 mock 要点**：capturetest 必须给 body 加 is-mobile 类
（否则 body.is-mobile 覆盖样式测不到），且 modal contentEl 要给
position:fixed;inset:0 模拟全屏（否则 flex:1 撑不开，正文占比断言失败）。

capturetest 26 → 29 例（零边框 5 + 透明背景 3 + 字号层级 2 + 正文占比 + 触摸区 2）。
全量 285 例通过。版本 0.6.24，提交 525fdc5。

## 真机截图修 5 项 + 发现主题覆盖根因（v0.6.25）

**根因（重要）**：Obsidian 主题（用户用 Minimal）会给 modal 内的
input/textarea 加自己的边框与底色，单类选择器 `.cardbox-capture-input`
压不过。且关闭按钮 `.modal-close-button` 是 **modalEl 的直接子元素**，
之前把 class 打在 `titleEl.parentElement` 上，选择器根本命不中。

**解法**：class 打到 `this.modalEl`（`.cardbox-capture-modal`），
所有规则写成 `.cardbox-capture-modal .xxx` 两层选择器；
并显式重置 `:hover/:focus/:active` 的 border/background/box-shadow
（主题常在伪类上加样式，只重置默认态不够）。

**5 项改动**：
① 关闭按钮 display:none（连 .modal-title 一起）
② 标题贴顶：padding 0 14px（上下 0）+ height 52px + line-height 52px
   （单行垂直居中）；padding-left 14px = modal border-radius 14px，
   使首字符正对圆角与直边的切点
③ 正文 min-height 200px + 容器 min-height 62vh
④ 连续创建 background transparent + border-radius 999px
⑤ footer padding-bottom 8px（去掉 safe-area-inset 叠加，贴键盘 5~10px）

**测试 mock 升级（关键经验）**：Modal mock 原来只有孤立 contentEl，
必须完整模拟 `container > modalEl > (close-button, title, content)`，
否则「关闭按钮隐藏」「modalEl 作用域样式」这类问题在 mock 里永远测不出来
——这正是前几轮改了没生效却测试全绿的原因。
captureshot 另加 340px 键盘占位区模拟真机输入法。

capturetest 29 → 38 例。全量 294 例通过。版本 0.6.25，提交 93dc19e。

## 新建卡片下部自适应贴合输入法键盘（v0.6.26）

用户要求：卡片下部自动贴合输入法 UI 顶部。

**实现**（CaptureModal.bindKeyboard）：
- 监听 window.visualViewport 的 resize + scroll
- 键盘高度 = window.innerHeight - visualViewport.height
- keyboard>0 时 modalEl.style.transform = translateY(-keyboard px)
- 收起清空复位，transition 0.15s 平滑，onClose 清理

**平台差异**：iOS innerHeight 不变、vv 缩小（靠这个计算）；
Android adjustResize 两者同步缩 → keyboard≈0，系统自动处理，不重复顶。

**配合 CSS**：
- .cardbox-capture-container（= modalEl.parentElement = .modal-container）
  手机端 align-items: flex-end（之前 Obsidian 默认 center 居中，卡片悬中间不贴底）
- .cardbox-capture-modal 手机端 width 100% + max-height calc(100vh - 60px)

**测试经验**：keyboardtest 必须：
1. 页面里注入 styles.css（否则 align-items flex-end 测不到）
2. 假 visualViewport 用 `get height(){return mockVvHeight}` getter，
   手动改 mockVvHeight 后触发 listeners 模拟键盘弹出/收起

全量 300 例通过（keyboardtest 6 例新增）。版本 0.6.26，提交 0de3ecb。

## 键盘贴合修复：改用 Platform.mobileKeyboardHeight（v0.6.27）

用户反馈微信输入法弹出后卡片底部仍不贴键盘。

**根因**：v0.6.26 用 `window.innerHeight - visualViewport.height` 算键盘高度，
但 Android adjustResize 下两者**同步缩小**，差值 = 0，永远算不出键盘高度。
微信输入法正是这种场景（visualViewport 不变或同步缩）。

**正确信号（关键知识）**：Obsidian 移动端内置了
`Platform.mobileKeyboardHeight` / `Platform.mobileSoftKeyboardVisible` /
`Platform.mobileDeviceHeight`（官方 .d.ts **未导出**，运行时存在，
社区 @obsidian-typings 的 PlatformEx 类型证实）。这些由 Obsidian 内部
Capacitor Keyboard 插件维护，特殊键盘也正确上报，不依赖 WebView。

访问方式：`(Platform as any).mobileKeyboardHeight`。

**新逻辑**：
1. 键盘高度优先取 Platform.mobileKeyboardHeight（visible 时），
   visualViewport 差值仅兜底
2. 上移量 = keyboard − (deviceHeight − innerHeight)：减掉 adjustResize
   已缩小的量，避免双重上移
3. 属性值无事件 → 150ms 轮询 + resize/scroll 即时响应

**测试**：keyboardtest 重写为微信输入法场景（vv 不变、仅 Platform 上报），
证明旧方案测不出这个真实失效。全量 300 例。版本 0.6.27，提交 c061833。

**经验**：处理 Obsidian 移动端键盘，首选 Platform.mobileKeyboardHeight，
不要自己算 visualViewport（Android adjustResize 会失效）。
