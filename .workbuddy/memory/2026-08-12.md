## 白板光标跳修复 v2：bump 检测改 Canvas 内部 API（v0.6.17）

**背景**：v0.6.14 的修复（isFileBeingEdited DOM 探测）无效，用户实测光标仍跳。

**定位过程**（用户实验数据）：
- 禁用 CardBox 不跳 → 根因确实在 bump 二次写盘
- 埋点显示写文件仍是双写 → isFileBeingEdited 完全没拦住
- 用户验证命令：DOM 只有 1 个 .canvas-node 而 API `view.canvas.nodes` 返回 8 个
  → **Canvas 按视口虚拟化渲染节点，DOM 探测从根上不可靠**；
  `data-path` 属性是否存在也未验证（很可能没有）

**修复（v0.6.17，提交 29c3e37）**：isFileBeingEdited 改为三层检测：
1. 普通 markdown leaf 匹配 file.path（原有）
2. **Canvas 内部 API**：遍历 `getLeavesOfType('canvas')` → `view.canvas.nodes`
   （全量 Map）→ file 节点路径匹配且 `child.getEditor` 存在（编辑态）→ 命中
3. DOM 兜底（仅 API 不可用时）

**验证手段**：maybeBumpUpdated 跳过时输出 `[CardBox:index] bump 跳过：文件正在编辑`
日志——用户可直接在控制台确认拦截是否生效，不必再看双写。

**经验**：Obsidian Canvas 的节点渲染是虚拟化的（按视口），任何针对
`.canvas-node` 的 DOM 探测都不可靠；检测白板内节点状态要用
`view.canvas.nodes` API。此为本次踩坑核心教训。

测试：build + npm test + loadtest + counttest 全过。已打包
release/cardbox-0.6.17-mobile.zip 并同步 test-vault。

## 白板光标跳修复 v3：编辑态判定改用 child 非空（v0.6.18）

**v0.6.17 仍无效**（用户：控制台无任何日志 = 拦截没发生）。
用户实测数据（JSON.stringify 展开）：`view.canvas.nodes` 中 file 节点的
`child.getEditor` **全部 undefined**（该 Obsidian 版本不存在），但
**只有正在编辑的卡片 child 非 null**（childType "t"，字段含 editorEl/dirty/
editable/requestSave/previewMode = 编辑器视图），其余 7 张卡片 child 全为
null。

**修复（v0.6.18，提交 bdb0dd3）**：isFileBeingEdited 第②层从
`typeof child?.getEditor === 'function'` 改为 **`n.child != null` 即编辑态**。

**教训**：Canvas 卡片 child 字段是"编辑态加载"的可靠信号，比猜测内部方法名
（getEditor）稳得多。以后探测 Obsidian 内部结构必须先拿 JSON 展开的真实
字段，不要猜方法名。

测试：build + npm test 全过。已打包 release/cardbox-0.6.18-mobile.zip 并
同步 test-vault。

## v0.6.19 数字颜色 + CaptureModal + 视图模式持久化

按用户四点反馈实现：

**1) 展开数字改主题色柔化**：原本灰底（`text-muted`/`background-modifier-border`），
用户说灰色不合适。改为 color-mix 22% + inset shadow 35% 的主题色淡蓝，
保留蓝色系语义但明显比默认浅（提示已展开）。

**2) CaptureModal 简化**：
- 标题 input 独立到卡片最顶部（.cardbox-capture-title-row）
- 编辑区与标题栏之间无边框、编辑区自身也无边框
- 只在 footer（保存按钮上方）加分割线
- 连续模式移到 footer 左侧，与保存按钮同行（space-between）
- footer padding-bottom: max(12px, 52px) —— 按钮整体上移一个自身高度
- 去掉取消/关闭按钮（隐藏 modal-close-button，无关闭入口）

**3) 视图模式持久化（修「跳转后变单列」）**：
- 根因：FilterBar.mode 是实例变量；Obsidian 切到笔记再切回 → 视图 leaf
  重建 → FilterBar 从 settings.defaultViewMode='card' 初始化 → 双列丢失
- 修复：onModeChange 回调里把 mode 写入 settings.defaultViewMode 并 saveSettings
- 验证 modepersist.mjs 5 例：切 masonry → 销毁视图 → 重建 → 仍是 masonry

**CSS 重构**：.cardbox-capture-header → .cardbox-capture-title-row；
删除 .cardbox-capture-toolbar/tools/tool（用户要求去掉工具按钮）。

全量 270 例通过（capturetest 15 + modepersist 5）。
版本 0.6.19，提交 05cebf5。

## CaptureModal 主题自适应 + 标题贴顶 + footer 上移（v0.6.23）

按用户三点反馈：
1. 不再纯黑白，全改 Obsidian 主题变量（自适应深浅主题）：
   background var(--background-secondary)、标题/mode box
   var(--background-primary) + var(--text-normal) + 主题边框，
   编辑区 var(--text-normal)

在浅色主题本来就是白——测试断言不能写"非纯白"，要写"用了主题变量/
非透明 + 圆角"。主题自适应的正确验证方式是「用了 var() 而非硬编码」。

全量 282 例通过。版本 0.6.23，提交 63459dd。
